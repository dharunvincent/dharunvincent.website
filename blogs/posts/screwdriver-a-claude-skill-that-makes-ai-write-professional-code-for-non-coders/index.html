Screwdriver: A Claude Skill That Makes AI Write Professional Code for Non Coders

AIClaudeProductivity

The problem nobody warns you about

AI lets anyone build an app now. I'm living proof. I started as a civil engineer, became a business analyst, and spent four years as a product manager on HBO Max. I have never written code for a living. Yet today I build my own tools and side projects with Claude Code.

But here's what nobody tells you. When you can't read code, you can't tell good code from bad code. The AI says "Done!" and you smile and nod. It looks like it works. Then one day a payment silently fails, or a file disappears, or a small fix turns into a three hour loop that eats your entire token budget.

You don't know what you don't know. And that's dangerous when you're the one shipping the product.

So I built Screwdriver

Screwdriver is a free, open source skill for Claude. A skill is a set of instructions Claude follows every time it does a certain kind of work. This one kicks in whenever Claude writes, changes or reviews code.

Think of it as a senior engineer sitting next to Claude, quietly making sure it does things the right way. You don't need to understand the rules. Claude does. You just get better code and plain English reports.

It's built for two kinds of people:

  • People like me who don't code but want to build real products with AI: product managers, founders, designers, analysts, students, anyone with an idea.
  • Engineers who want a consistent standard, without Claude bulldozing a codebase that already works.

The core ideas come from a well known engineering book, Functional Programming in Scala. Don't let the name scare you. The rules work in any language, and I rewrote them in simple words.

What it makes Claude do

Screwdriver gives Claude 12 rules, a self check, and a few habits. Here are the ones that matter most, in plain English.

  1. Never fail silently. Every error is caught and handled. No more "payment failed but the receipt email went out anyway".
  2. Plan for missing data. If something can be blank, the code says so and deals with it, instead of crashing when a user skips a field.
  3. Prove it works. Claude can't say "done" because the code looks fine. It has to run it and show the real result. For a bug, it first shows the bug happening, then fixes it, then shows the same check passing.
  4. Write down the rules first. For anything important, like money or permissions, Claude first writes what must always be true ("the total is never negative") and then tests it with hundreds of random inputs.
  5. Keep it simple. Small pieces that each do one job. No clever tricks. Clear comments explaining why, for whoever touches the code next. That might be you, six months later.
  6. Save your work in two places. Every finished piece is saved on your computer and on GitHub. If GitHub goes down, nothing is lost. Claude keeps working locally and uploads everything once it's back.
  7. Never commit your secrets. Passwords and API keys never get uploaded by accident.

At the end of every task you get a short report, four lines at most: what was done, why, what could go wrong, and whether it needs your decision.

Why this matters if you can't code

You can't review the code, so the rules review it for you. An engineer would spot an empty error handler in seconds. You and I wouldn't. Screwdriver makes Claude check its own work against a fixed checklist before it reports back.

"It works" finally means it works. The prove it works rule is the one I'm proudest of. My engineer colleague pointed me to it, and it closed the biggest gap. You get evidence, not confidence.

It saves tokens without cutting corners. Most wasted tokens come from the AI trying fix after fix on a wrong idea. Screwdriver stops that. Claude reads only the files it needs. For big changes, it shows you a short plan before writing a single line. And if two honest attempts fail, it stops, tells you what it learned, and works out the next step with you. Tests, proof and comments are never cut to save tokens.

You stay in charge. You pick between guided mode (full rules, plain English explanations) and expert mode (respects existing code, only flags the serious stuff). Claude asks once per project and remembers.

Try it in two minutes

If you use Claude Code, open Terminal and paste this one line:

git clone https://github.com/dharunvincent/screwdriver.git ~/.claude/skills/screwdriver

Restart Claude Code, and that's it. Screwdriver kicks in automatically whenever you ask Claude to write or fix code. To update later, run git pull inside that folder.

The full rules, worked examples and install steps are on GitHub: github.com/dharunvincent/screwdriver.

Help me make it better

Screwdriver is MIT licensed, so it's free to use, change and share. If you're an engineer, I'd love your pull requests, especially language specific examples. If you're a non coder like me, try it and tell me where it confused you. That feedback is just as valuable.

I'm a product guy. I can't write the code, but I know what good looks like. Screwdriver is how I make sure the AI knows it too.
